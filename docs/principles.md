# Principles

Each rule below exists because something went wrong without it. The reason is given after each one.

## Structure

**One project, several threads.** Each area of work or life gets its own chat with its own charter and folder. A single chat that holds everything runs out of context, and its oldest facts are the first to go.

**Threads do not overlap.** Each thread owns its area. Where two touch, each says so in one line and leaves the work to the owner. Without this, two chats give the same person two different answers about the same thing.

**A reading order at the top of every context.** A new chat in a thread reads the same documents in the same order before it says anything. Chats that skip the reading invent what they could have looked up.

**One constitution, kept short and stable.** The project instructions hold the standing orders and the thread table. Anything that changes from week to week goes in a log. Instructions that carry live status go stale within weeks, and every chat then spends its time reconciling them.

## Records

**The log wins.** Each thread keeps a dated log that only grows. The log outranks older documents, and the person outranks the folder. A clear order of precedence ends arguments about which document is current.

**Record facts the same day, in the person's words.** Each paraphrase changes a fact a little. Quotation marks show which words are theirs.

**Changed decisions get a new entry.** The new dated entry says what it replaces, and the old entry stays. The history of a decision is often what the next chat needs.

**Record extracts, with corrections.** When a thread starts, a sourced digest records what the project already knows about its area. Its first section lists where older documents are wrong. Older documents stay unchanged, and the extract carries the corrections.

**Canonical documents, kept by one chat.** A record of facts with consistency rules, and a list of people with handling notes, both live in one place. One chat (the master) changes them, from the logs. A fact that several chats can each edit soon has several versions.

**One copy of the house style.** Folders point to it. Copies taken on different days drift apart.

## Behaviour

**Never invent. Ask.** A plausible invented fact is worse than a gap, because it gets copied.

**Numbered questions, in one batch.** Each is answerable in a word or a line. The person can answer from a phone, in order, and nothing gets lost.

**Handling by omission.** If a subject is not in the documents, no chat raises it. If a name seems to be missing from a story, it is missing on purpose. This protects private matters without listing them anywhere.

**PRIVATE markers.** A sensitive log line is marked PRIVATE. Summaries and documents leave it out. The fact is still recorded, so no chat has to rediscover it.

**Mistakes get a correction and a record.** Say what it was, fix it and log it. An apology adds nothing the next chat can use.

## Lists

**One list per thread, plus a master.** Items copy from a thread's list to the master list, and only in that direction. A two-way copy produces duplicates that disagree.

**Ask before adding.** Items drawn from charters, other threads or inference go to the person as a question. Lists that fill with things the person never asked for stop being read.

**Read before you write, and pin the write.** Every write to an existing item names the version last read. If the person ticked it on the page in the meantime, the write fails, and the chat reads again. Without this, a chat overwrites the person's own changes.

**Do not nag.** Roll items forward without comment. Acknowledge real wins in a line. Leave the weekend light. A list that scolds gets abandoned.

**Decide what is never tracked.** Some things should not be on a list, such as items the person has asked never to see. Write the exclusions down so no chat re-adds them.

## Continuity

**A retiring thread writes an operating guide.** When a thread retires, merges or moves to a fresh chat, it writes a manual for its successor: where everything lives, how to use it, what is never tracked, the open questions and a snapshot of the state. A summary loses the rules, so the retiring thread writes a guide.

**Re-read after compaction.** When a chat's history is replaced by a summary, it re-reads its context, the house style and its log before it replies. A summary keeps the gist and drops the rules, and a chat that answers from the gist breaks them.

**A master merge, on a rhythm.** The master chat reads the logs, proposes changes to the canonical documents, and puts contradictions to the person to resolve. Logs that never fold back into the canon leave each thread with its own version of the truth.
